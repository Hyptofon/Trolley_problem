# Технічне завдання — «Дилема вагонетки»

**Версія:** 1.0  
**Тип продукту:** невеликий інтерактивний вебсайт для анонімного навчального голосування  
**Мова інтерфейсу:** українська  
**Основний принцип:** одна дилема, рівно два варіанти вибору, без інших сценаріїв і додаткових анкет.

## 1. Мета і межі

Створити власний візуально якісний адаптивний сайт, на якому учасник бачить класичну проблему вагонетки, обирає одне з двох рішень і спостерігає короткий не-графічний анімований наслідок. Рішення анонімно зберігається. Організатор входить до захищеної адмінпанелі та бачить загальну кількість голосів, голоси і відсотки для кожного вибору, ефектні графіки; може показати статистику аудиторії у презентаційному режимі.

Це навчальний демонстраційний проєкт для невеликої аудиторії, а не система захищених виборів. Без реєстрації учасників неможливо достовірно гарантувати «одна людина — один голос».

### Незмінні межі обсягу
- Лише класична ситуація: некерована вагонетка наближається до п'ятьох людей; переведення стрілки направить її на колію з однією людиною.
- **Рівно 2 відповіді:** `stay` — **«Не втручатися»** (під загрозою п'ятеро); `switch` — **«Перевести стрілку»** (під загрозою одна людина).
- Жодних інших моральних сценаріїв, відкритих запитань, тестів особистості, збору імен, email, телефону, віку, геолокації, реєстрації учасників, оцінок правильності вибору або рейтингу осіб.
- У публічній частині тільки екран дилеми й екран наслідку/подяки. Статистика доступна організатору, а не відвідувачам за замовчуванням.

## 2. Функціональні вимоги

### FR-01. Сторінка `/`
- Короткий зрозумілий заголовок «Проблема вагонетки», пояснення ситуації людською українською, два чітко сформульовані варіанти.
- Оригінальна адаптивна 2D-сцена на SVG/CSS: дві колії, розгалуження, вагонетка, умовні силуети п'яти й однієї людини, важіль/стрілка; кількість людей зчитується і в тексті, і в графіці. Жодної кривавої або шокуючої візуалізації.
- Обидва варіанти оформлені доступними, контрастними, великими кнопками з текстом. Наявність зображення не є передумовою розуміння вибору.
- Поки відправлення триває, повторні натискання блокуються. Анімація наслідку стартує тільки після підтвердження збереження голосу сервером.
- При успіху показати відповідну коротку анімацію й нейтральний висновок («Ви обрали ...»), «Дякуємо за участь». Не давати моральної оцінки рішенню.
- При помилці мережі показати зрозумілу помилку та кнопку **«Спробувати ще раз»**, повторити той самий запит із тим самим ідентифікатором (ідемпотентність); не показувати неправдивого «голос враховано».
- При повторному заході з браузера, який уже підтверджено голосував, показувати завершений стан, не відкривати можливості ще одного голосу в стандартному інтерфейсі.

### FR-02. Проста анонімність і захист від випадкового дублювання
- Не потрібен акаунт і авторизація учасника.
- При першому відвідуванні генерувати криптографічно випадковий неприв'язаний до особи UUID (`crypto.randomUUID`); зберігати у localStorage як псевдонімний маркер браузера.
- Сервер зберігає максимум один голос на цей маркер; дублікати й повторення після мережевої помилки не збільшують лічильники.
- Якщо повторно надсилається інший вибір із того самого маркера — початковий голос не змінюється. Визначити й протестувати однозначну поведінку та повернути клієнту статус «вже голосували».
- Не збирати IP, User-Agent, email, fingerprint; не вводити сторонніх аналітичних трекерів. Якщо зовнішні платформи автоматично ведуть технічні логи, не обіцяти абсолютної анонімності в юридичному сенсі.
- Чітко зазначити в README та за потреби в короткій примітці UI: обмеження за браузером легко обходиться очищенням даних/іншим пристроєм і не є підтвердженням унікальності людини.

### FR-03. Адмінпанель `/admin`
- Публічна сторінка `/admin` може показувати тільки форму входу; **жодна статистика не повинна потрапляти в HTML, JS-бандл чи відповіді API до успішної серверної авторизації**.
- Одна роль: організатор. Надійний пароль конфігурується через серверний секрет платформи; не зберігати пароль чи ключі у фронтенді, `VITE_*`, Git або публічному сховищі.
- Після успішного входу — короткоживуча серверно перевірювана сесія в підписаному `HttpOnly`, `SameSite=Strict` cookie, `Secure` для HTTPS. Реалізувати коректну поведінку на localhost. Вихід із сесії.
- Захищений API статистики перевіряє автентифікацію **самостійно**, навіть якщо хтось напряму звертається до URL або підробляє стан React.
- Панель показує: загальну кількість голосів, абсолютні значення для `stay` і `switch`, відсотки (коректні для 0 голосів, точність 1 знак або цілі за чітким правилом), дату останнього оновлення, виразну діаграму і зрозумілу легенду.
- Автооновлення результатів із помірним інтервалом (наприклад, раз на 15 секунд тільки коли сторінка активна) + ручна кнопка оновлення; `Cache-Control: no-store`.
- Презентаційний режим: великий екран із тими ж числами, без меню та службових віджетів, контрастним текстом, за потреби Fullscreen API і виходом назад. Не показувати реальні дані без авторизації.
- Порожній стан, завантаження, таймаут, помилки сервісу, завершення сесії, неправильний пароль відображаються коректно.
- **Не вимагати** функції видалення голосів, редагування відповідей, імпорту персональних даних та додаткового менеджменту опитувань.

### FR-04. Збереження та статистика
- Google Sheets — **зовнішнє сховище**, без власної БД.
- Google Apps Script Web App — вузький адаптер для запису голосу й отримання агрегатів. Таблиця залишається приватною. Apps Script запускається від акаунта власника; доступ до вебвиклику може бути анонімним, але кожен запит має проходити перевірку спільного серверного секрету.
- Клієнт **ніколи** не викликає Google Apps Script напряму. Всі запити йдуть на same-origin API Cloudflare Pages Functions, який додає секрет, перевіряє відповіді й коректно обробляє редиректи Google ContentService. Цим усуваються проблеми CORS та витоку секрету.
- У Google Sheet зберігати лише `timestamp`, `participantId` (або односторонній псевдонімний хеш), `choice`. Перевірка/створення шапки таблиці — окрема безпечна інструкція/`setup` функція. Таблиця не публікується.
- Для конкурентних `appendRow` і перевірки дублікатів застосувати `LockService.getScriptLock()`, `try/finally`, обмежений таймаут; при зайнятості — явна контрольована помилка, не мовчазна втрата голосу.
- Apps Script рахує статистику за фактично збереженими голосами, без довіри до фронтенд-лічильників.
- Жодних hard-coded демоголосів у production. Наявність mock data допускається лише у явно позначеному локальному деморежимі та тестах.

## 3. Архітектура

```text
Відвідувач без входу
  └── React + Vite + TypeScript (статичний сайт на Cloudflare Pages)
         └── POST /api/vote (Cloudflare Pages Function; same-origin)
                └── POST Google Apps Script (секрет лише на сервері)
                       └── приватна Google Sheet (реальні голоси)

Організатор
  └── /admin (форма входу → захищений інтерфейс)
         ├── POST /api/admin/login → коротка підписана cookie
         ├── POST /api/admin/logout
         ├── GET /api/admin/session
         └── GET /api/admin/stats (перевірка cookie)
                └── Google Apps Script → агрегація Google Sheet
```

### Рекомендовані технології
- UI: React, TypeScript (`strict`), Vite, Tailwind CSS.
- Анімації: Motion або акуратні CSS/SVG animation. Уникати зайвих важких залежностей.
- Діаграми: Recharts (або власна accessible SVG-діаграма, якщо вона краща для швидкості).
- Роутинг: React Router; рівно `/` і `/admin` плюс обробка 404.
- API: Cloudflare Pages Functions (без окремого сервера, деплояться разом із сайтом).
- Сховище: Google Sheets; інтеграція: Google Apps Script; ніякого Supabase/Firebase/Postgres/D1/KV.
- Тестування: Vitest, React Testing Library, MSW або еквівалент для mock API, Playwright; ESLint і TypeScript check.
- CI: простий GitHub Actions workflow для типізації, lint, unit/integration, e2e та production build без автоматичного деплою.

### Приклад контрактів (уточнити типи та статуси в реалізації)

`POST /api/vote`
```json
{ "participantId": "UUID-v4", "choice": "stay" }
```
Успіх:
```json
{ "status": "recorded", "choice": "stay" }
```
Повтор:
```json
{ "status": "already_voted", "choice": "stay" }
```
Помилка: контрольоване `{ "error": { "code": "...", "message": "..." } }` зі статусом 400/409/429/502/503/504 відповідно до ситуації. Зберегти ідемпотентність: повтор після таймауту не повинен дублювати голос.

`POST /api/admin/login`: пароль у JSON body, серверна перевірка → HttpOnly cookie.  
`GET /api/admin/session`: `{ "authenticated": true|false }`, без секретів.  
`POST /api/admin/logout`: видалення cookie.  
`GET /api/admin/stats` (авторизований):
```json
{
  "total": 100,
  "stay": 40,
  "switch": 60,
  "stayPercent": 40,
  "switchPercent": 60,
  "updatedAt": "2026-11-05T16:00:00.000Z"
}
```

Обробити: некоректні/занадто великі JSON, невідомі значення `choice`, відсутність конфігурації, невалідні UUID, методи HTTP не за контрактом, повільну/недоступну Google-службу, пошкоджений формат upstream відповіді, втрату сесії. Не передавати внутрішні stack trace клієнту.

## 4. Дизайн та доступність
- Виразний авторський стиль: темний графітовий фон, світла типографіка, один акцентний колір для важеля/активного рішення; обдумана композиція замість шаблонних карток. Колір не має бути єдиним способом відрізнити вибори.
- Адаптивність для 360px, 390px, 768px, 1024px, 1440px; ні горизонтальному скролу, ні обрізанню тексту чи сцени.
- Дві кнопки та весь процес повністю керовані клавіатурою; фокус видно, є зрозумілі ARIA-повідомлення про статус, семантичні заголовки та текстові описи сцени.
- Орієнтир WCAG 2.2 AA: контрасти, цільові розміри натискання, масштабування 200%, мітки форм і помилок.
- Повага до `prefers-reduced-motion`: мінімізувати/прибирати рух, але показувати той самий результат; можливість пропустити довгу анімацію.
- Не використовувати шок-контент, зображення травм або смертей. Наслідки подаються словами і символічно.
- Жодних нав'язливих попапів, сторонніх трекерів, реклами чи додаткових питань.

## 5. Захист і конфігурація
- Секрети в `.dev.vars` локально й зашифрованих Cloudflare Secrets у production. `*.example` містить тільки плейсхолдери.
- Очікувані секрети: `APPS_SCRIPT_URL`, `APPS_SCRIPT_SHARED_SECRET`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`. У Google Script Properties — відповідний спільний секрет і ідентифікатор Spreadsheet.
- Вхід: безпечно перевірити пароль, коректно підписати сесію через WebCrypto HMAC, перевіряти термін дії. Cookie має захист від XSS-читання; для state-changing endpoints контролювати Origin і CSRF через same-site правила; для сторонніх Origin відмовляти.
- Для публічного логіну задокументувати доцільність Cloudflare rate limiting/WAF/Access або еквівалентного захисту від перебору. Без постійного серверного стану не заявляти про повну стійкість до brute force.
- Налаштувати `Content-Security-Policy` та доречні заголовки безпеки, заборонити кешування приватних API. Не логувати паролі, тіло голосування або participantId.
- Протидія повторним голосам **best effort** на рівні браузерного UUID; не представляти це як надійну ідентифікацію людей.

## 6. Локальна робота, запуск і деплой
- `npm install` і `npm run dev` мають давати готову локальну UI-демонстрацію без Google-акаунта, з чіткою видимою позначкою «Демо — голоси не зберігаються». Для перевірки реального інтегрованого режиму надати команду локального запуску Cloudflare Functions, тестові секрети, контрольований mock Google upstream.
- `npm run build` створює production збірку; `npm run dev:full` (або документований аналог) дозволяє локально перевірити UI+API. Жодної залежності від публічної Google-таблиці для звичайного запуску тестів.
- README містить ПОКРОКОВО: створення Google Sheet, додавання/запуск Apps Script, налаштування Script Properties, `Deploy → New deployment → Web app` (`Execute as me`, анонімний доступ за потреби), одержання URL, Cloudflare секрети, локальну перевірку, публікацію сайту, відкриття `/admin`, перевірку голосу з іншого пристрою і повернення до приватної таблиці. Уточнити, що сам сайт усе одно публікується один раз, а скрипт теж потребує web app deployment; окремий сервер і власна БД не потрібні.
- Не деплоїти, не створювати реальних Google/Cloudflare ресурсів і не змінювати облікові записи без дозволу та доступу користувача. Якщо не вистачає секретів/доступу, завершити весь код і автоматизовані тести, а фактичний production smoke test позначити як `NOT RUN — external credentials required` із конкретними діями.
- Зберігати джерела у репозиторії, включно з Apps Script, тестами, `.env/.dev.vars.example`, README, документацією рішення та інструкцією деплою.

## 7. Обов'язкове тестування

### Unit
- Семантика обох виборів і текст наслідку.
- Генерація, стабільність та відновлення participantId.
- Правильний UI state machine (до вибору, запит, записано, дублікат, помилка, повтор).
- Відсотки: 0/0, 1/0, 0/1, округлення, великі значення, некоректні числа.
- Валідація запитів/відповідей, формування безпечних помилок.
- Підписування, верифікація, прострочення/пошкодження cookie, невірний пароль.

### Frontend integration (React Testing Library + mock network)
- Сцена й рівно дві кнопки вибору.
- Успішний кожен із двох варіантів.
- Швидке подвійне натискання; спільний participantId при повторі.
- Network error, timeout, повторна спроба без дублювання та без хибного success.
- Повернення в браузер після голосування; reduced-motion; keyboard navigation.
- Адмінпанель: логін, 401, успішне завантаження, пусті дані, помилка, автооновлення/пауза, презентаційний режим.

### Backend/API integration
- Публічний API не приймає сторонні/некоректні значення.
- Secrets ніколи не повертаються у браузер.
- Без автентифікації `/api/admin/stats` повертає 401; відмова після logout/закінчення сесії.
- Коректне перенаправлення до Apps Script, обробка redirect ContentService, таймаут/5xx/пошкоджена відповідь.
- Перевірка Origin та CSRF для state-changing endpoints, безпечне кешування.
- Apps Script із моками Google API: невірний секрет, некоректний голос, перший голос, повтор, зміна відповіді після першого голосу, гонка конкурентних запитів через LockService, стабільні агрегати.

### E2E (Playwright)
- Desktop Chromium, mobile viewport, бажано також Firefox/WebKit якщо середовище підтримує.
- Повний шлях від головного екрана до зарахованого голосу для обох рішень (тести незалежні, mock backend).
- Повторна відправка/повторне відкриття не додає голос.
- Помилка API й retry.
- Неправильний/правильний пароль, недоступна статистика без cookie, logout, перегляд діаграми, fullscreen fallback.
- Доступність: автоматичний axe-аудит критичних сторінок і ручний checklist клавіатури/reduced-motion.

### Quality gates
`npm run typecheck`, `npm run lint`, `npm run test`, `npm run test:coverage`, `npm run test:e2e`, `npm run build` — мають працювати і бути зеленими локально. У CI дублювати ключові перевірки. Заборонено `test.skip`, фейкові PASS, порожні тести, вимкнення лінтингу заради проходження. За неможливості запуску чітко вказати команду, лог і причину.

## 8. Критерії прийняття (Definition of Done)

- [ ] Одна й тільки одна дилема, рівно 2 варіанти; жодного додаткового анкето-сценарію.
